## 建議修正順序

1. **機械修正（約 1 小時，風險低）**：連結、函式命名、`Agg`。用腳本批次處理。
2. **A 類程式錯誤（約 25 個場景）**：每個場景改程式、重跑、重寫 README 結果和結論，一個場景一個 commit。符號和單位錯誤（S009、S025、S035、S046 等）修起來快；S041、S043、S045、S050 要重新設計部分邏輯。
3. **B 類比較無鑑別力（約 15 個場景）**：要調整情境讓策略之間真的有差別，例如讓逃跑者真的會躲（S011、S013）、讓衝突真的會發生（S031）。可能要同時修改卡片。
4. **C、D 類文件問題**：大多在步驟 2、3 重跑時一起更新。
5. **執行時間**：S042、S045、S030（GIF）、S020 超過 10 分鐘，修正時順便降低蒙地卡羅次數或 GIF 幀數。

6. **場景卡片的連結（2026-10-23 補查）**：100 張卡片（含 3d/）裡有約 290 條壞連結，多數可依場景編號自動修正；指向 `domains/<domain>.md` 的應改為 `domains/<domain>/README.md`；Domain 5 沒有 `domains/05_special_entertainment/README.md`。等 S001–S050 的修正分支全部合併後再批次處理，避免和正在修改卡片的分支衝突。掃描時要排除程式碼區塊（S093、S098 有 `x[k](t)` 被誤判為連結）。
7. **M7 連結文字（2026-10-24 補查）**：outputs README 的 Related Scenarios 連結文字和卡片標題只是大致相符（例如「S048 Lawnmower Coverage」vs 卡片「S048 Full-Area Coverage Scan (Lawnmower)」）。合併後統一改成「編號 + 卡片完整標題」，M7 的判定也改為完全一致。

S051 是今天新做的，沒有在這次 review 範圍內。修正前 50 個時會用同樣的標準再檢查一次。
