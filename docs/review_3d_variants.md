# 3D 版本 Review（2026-10-24）

> 檢查標準：[REVIEW_STANDARD.md](REVIEW_STANDARD.md)（M1–M8、C1–C10），和 [review_S001-S050.md](review_S001-S050.md) 相同。範圍是現有的 23 個 3D 版本（`*/3d/`），在 main 5a8b39b 上審查，每個程式都在獨立 worktree 跑兩次。
> 類型：A 程式錯誤、B 比較沒有鑑別力、C README 過期或描述錯、D 參數不符。

## 總覽

- **23 個都沒通過：20 個 HIGH、3 個 MED。** 每個程式都能跑，兩次結果也一致，但 README 的結論大多沒有程式結果支持。
- **很多 2D 已經修掉的 bug 在 3D 版還在**，因為 3D 是從舊的 2D 程式改出來的。例如：
  - S008 卡爾曼濾波器用真實位置當初值
  - S009 HJI 方程正負號錯誤
  - S016 比例導引從靜止起步
  - S022 RRT* 成本沒有往下傳
  - S029 中途不回倉庫，載重超過上限
- **已 commit 的圖片全部和現在程式畫出來的不一樣**（有 0.1–5% 的像素不同），所以要全部重新產生。
- **好幾個的 z 軸變化只是撞到高度上下限造成的**，不是真正的 3D 行為（S011–S014、S020、S022）。
- **S014、S019 的程式和 3D 卡片描述的是不同情境**，而且沒有說明。

## 修正

和 2D 的流程相同：修正 agent 修改並 commit（一個場景一個 commit：`Fix S0xx 3D <name>: <主要修正>`）→ 另一個 fresh-context agent 獨立驗收 → 補修 → 通過後合併。所有圖片都要重新產生。

## 修正結果（2026-10-25）

**23 個 3D 版本都已修正並合併到 main。** 每批修完都由沒參與修正的 agent 依同一標準驗收：每個程式跑兩次，輸出要一致、重新產生的圖片要和 commit 的版本逐 byte 相同、README 數字要和程式輸出對得上。驗收提出的問題全部補修完，再驗一次通過才合併。所有圖片都已重新產生。

修正後仍沒達到卡片預期，或只是如實回報的地方（各 README 的 Deviations 和 Key Findings 都有寫）：

| 場景 | 狀況 |
|---|---|
| S002 | 「3D 優勢」不存在：直線逃跑和俯衝後逃跑差不多（2.19 vs 2.17 s）；螺旋的好處來自轉彎比較少，不是來自爬升 |
| S004 | 從上方或下方飛越障礙幾乎沒有好處（40 次裡只選了 6 次，平均多出 0.00 s） |
| S005 | 從高處或低處接近反而比較慢 |
| S010 | 對卡片的逃跑者，所有策略的結果都一樣（它會卡在角落）；俯衝從來沒有比直接追擊好 |
| S011 | 追擊者加上最後撲上去的階段後，逃跑者比較慢時一定被抓到；同速時逃脫次數不隨 N 單調減少 |
| S014 | 側翼無人機在卡片的設定裡沒有作用；誘餌和真目標雜訊相同時分類器表現接近亂猜 |
| S019 | 卡片佈局下重新最佳化從來沒有觸發，平均 −0.037 s，也就是沒有好處 |
| S020 | PPO 追擊者在 10 分鐘的預算內學不會追擊對象以外的逃跑者；原因寫在 README（effort penalty、高度優勢項的獎勵尺度） |
| S024 | 卡片的 PID 側向誤差 < 0.2 m 在 50 個種子裡全部沒達到 |
| S029 | 只考慮時間窗、不改倉庫選擇時，在卡片的時間窗下沒有贏過 Clarke-Wright；在嚴格時間窗下明顯比較好 |
